# Mini Booking

Одна переговорная, 9 часовых слотов в день (09:00–18:00), расписание на 7 календарных дней, включая сегодня и выходные.

## Зависимости и быстрый запуск

Нужен только Docker Desktop с Docker Compose. PHP, Composer, Node.js и npm устанавливаются **в контейнерах**.

```sh
./scripts/start.sh
```

- Интерфейс: http://localhost:8080
- JSON API: http://localhost:8000/api/slots (также доступен через http://localhost:8080/api/slots).
- При первом старте backend автоматически создаёт `.env`, APP_KEY, SQLite, применяет миграции и запускает Seeder.
- SQLite хранится в именованном volume `booking-data`; перезапуск и пересборка контейнеров сохраняют бронирования.
- `scripts/start.sh` последовательно собирает оба образа и запускает Compose. Это также обходит ошибку DNS при параллельной сборке в старом Docker Compose 2.0. На актуальном Docker Desktop можно использовать `docker compose up --build -d`.
- На старых версиях Docker используйте `docker-compose` вместо `docker compose`.

```sh
# Логи и остановка (данные сохраняются)
docker compose logs -f
docker compose down

# Отдельный запуск каждой части
docker compose up -d backend
docker compose up -d frontend

# Миграции и повторное заполнение расписания
docker compose exec backend php artisan migrate --force
docker compose exec backend php artisan db:seed --class=ScheduleSeeder --force

# PHPUnit, отдельная SQLite :memory: — рабочая база не затрагивается
docker compose exec backend php artisan test
```

Для проверки production-сборки frontend: `docker compose build frontend`. В ней запускается `npm ci && npm run build`, после чего файлы обслуживает nginx. Backend запускается встроенным сервером Laravel: этого достаточно для локального тестового задания, для production нужен отдельный PHP application server.

## Структура

- `backend/`: PHP 8.3, Laravel 12, PHPUnit 11, миграции, ScheduleSeeder, API.
- `frontend/`: Vue 3, Composition API, `<script setup>`, Vite, PrimeVue 4 (Aura).
- `frontend/src/composables/useBookings.js`: JSON API, сетевые ошибки и состояние загрузки.
- `compose.yaml`: backend и frontend/nginx, проксирование `/api` без необходимости CORS.
- Composer/npm lock-файлы фиксируют версии зависимостей.

## Окружение и время

Значения backend приведены в `backend/.env.example`. По умолчанию расписание работает в `Asia/Omsk`. Для другого пояса создайте `.env` **в корне проекта**:

```dotenv
APP_TIMEZONE=Europe/Moscow
```

Затем пересоздайте контейнеры: `docker compose up -d --force-recreate`. Настройка попадает в `config('app.timezone')`. Для воспроизводимого расписания выберите пояс до первого заполнения базы. Если менять его позже, старые слоты сохранят свои абсолютные моменты времени; Seeder добавит недостающие по новому поясу.

Начало и конец слотов хранятся как Unix timestamp (секунды, абсолютное время). Seeder строит календарные дни 09:00–18:00 в часовом поясе Laravel. API отдаёт ISO 8601 с UTC-смещением и имя часового пояса. Интерфейс явно форматирует даты/время в этом поясе, независимо от пояса браузера. Статус определяется сервером: `starts_at <= now` — прошедший. В интерфейсе граница дополнительно обновляется каждую секунду с поправкой на серверное время; окончательное решение всегда принимает API.

Seeder использует уникальный `slots.starts_at` и `firstOrCreate`: повторный запуск сохраняет ID и бронирования, на следующий день добавляет 9 слотов, историю не удаляет. Слоты начала сегодняшнего дня также создаются. Scheduler/cron отсутствуют; для продолжения расписания явно запустите Seeder. На старте контейнера Seeder также выполняется.

## API

### `GET /api/slots`

```json
{
  "timezone": "Asia/Omsk",
  "server_time": "2026-11-17T12:00:00+06:00",
  "data": [{"id": 1, "starts_at": "2026-11-18T09:00:00+06:00", "ends_at": "2026-11-18T10:00:00+06:00", "status": "available", "booking_id": null}]
}
```

Список отсортирован по началу; статусы `available`, `booked`, `past`. Прошедший статус имеет приоритет, но ID бронирования сохраняется для отмены. Имя и email в ответ не попадают.

### `POST /api/bookings`

```json
{"slot_id": 1, "customer_name": "Анна", "customer_email": "anna@example.com"}
```

- `201 {"id": 1}` — создано.
- `422` — стандартные ошибки Laravel в `errors.slot_id`, `errors.customer_name`, `errors.customer_email`.
- `409 {"message": "…"}` — слот занят или уже начался.

### `DELETE /api/bookings/{id}`

`204`, включая повторную отмену. Отмена физически удаляет запись: таблица `bookings` хранит только активные бронирования. История отмен не ведётся. Будущий слот снова доступен, прошедший остаётся прошедшим. Авторизация отсутствует по ТЗ, любой известный ID можно отменить.

## Целостность при одновременных запросах

`bookings.slot_id` имеет **UNIQUE** и внешний ключ. БД физически не позволяет создать две активные записи одного слота. В транзакции сначала выполняется запись в строку слота для получения блокировки писателя SQLite. После получения блокировки заново проверяется серверное время и наличие бронирования. Затем создаётся запись. Используются busy timeout 10 секунд и до 5 повторов транзакции при deadlock. Нарушение уникальности дополнительно преобразуется в `409`. Отмена удаляет запись и освобождает уникальный ключ.

## Интерфейс

Фильтр по дате, свободные/занятые/прошедшие слоты, форма с обязательными именем/email, отмена с подтверждением, блокировка действий во время запроса. При `422` ошибки показываются у полей; при `409` причина показывается в диалоге и расписание обновляется. Сетевые/серверные ошибки оставляют форму открытой для повтора. Ошибка обновления расписания видна отдельно и блокирует операции до успешного повтора, чтобы не работать со старыми данными. После успешной операции список обновляется без перезагрузки страницы.

## Проверки и объём

Проверено в Docker: production-сборка Vue, **8 тестов PHPUnit / 38 проверок**, создание и отмена через браузер, отображение при ширине 390 px. HTTP-проверка с 16 одновременными запросами дала **один 201 и пятнадцать 409**; после отмены слот снова свободен.

`BookingTest` покрывает успешное бронирование, повторный запрос (`409`, одна запись), отмену и повторное бронирование, границу «ровно сейчас», `422`, приватность и порядок списка, пояс, повторный запуск и расширение Seeder, уникальность непосредственно на уровне БД.
